Python validates the allowed tool name/arguments before execution, allows only one lookup, sends its actual result back with the matching provider call ID and permits at most two model requests. Further tool calls are rejected.

The final model message is requested as a JSON object containing one nonblank string reply. LLMReply is a Pydantic validation schema, not another trained AI model. The application parses/checks that text before saving or returning it. The API response adds the saved chat ID, model and server-generated tool_used. This is prompt-guided JSON plus application validation, not native provider-enforced Structured Outputs; valid formatting does not prove factual correctness.

SQLite stores successful conversations and optional tool traces in one transaction with parameterized values. A failed tool-row insert rolls back its parent chat. Failed exchanges are not logged, including a provider failure after a read-only lookup. GET retrieves saved fields/decoded JSON without another model request. Logging is not model memory; every POST starts a fresh exchange. Orders and statuses are fictional, and the service has no authentication or real business-system connection.
